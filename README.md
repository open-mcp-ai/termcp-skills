## [`DISPATCH.md`](./DISPATCH.md) —— 副产物，它凭什么这么说

一份完整记录：某天，一个 AI 在别人的机器上干了一天活。它修的坏东西、它判错的地方、哪些字符串救了它，以及它在一个能兜住它的环境里变成了什么样。

**它是副产物，不是入口。** 但值得读，因为它就是 SKILL.md 里大部分纪律的出处——每一条都能在里面找到当时付的代价：

| SKILL 里的纪律 | 出处 |
|---|---|
| 等长任务挂唤醒，不要空读 | §七 一直在轮询，大量来回烧在空读上（那天那条通道还是断的） |
| 硬拒绝别重试 | §九 `forbidden` 是硬拒绝，不是提醒 |
| 收尾分清关闭与删除 | §七 把正在用的通道一起杀掉了 |
| 错误文本是路标 | §八 全节：转折点都是被错误文本指出来的 |
| 读取位置只按结束偏移推 | 不在 DISPATCH 里——是工具行为本身，不问就会推错 |

**也给人读。** 如果你是工程师，想知道一个 AI 眼中这类工具真正的价值在哪、哪里会翻车——失败的部分可能比成功的部分有用。

## 一句话

**AI 不缺知识，缺一片能直接落地的地面。**

一个 AI 知道 `ffmpeg`、`tcpdump`、`openssl`、`systemd` 怎么用。但大多数工具面把它浪费掉了——预先想好的那串动词，是对它全部知识的一次有损投影。**别人想到的它能做，没想到的它就不会。**

终端不预先决定它用什么。它只提供执行和字节。于是它知道什么，就能做什么。

## 草稿：为什么写了好几遍

这份记录被写了好几遍，因为前几遍都不合格——**AI 写的时候默认读者脑子里已经装着他自己的处境。**

每一版的失败点都留着。因为"为什么这样写不行"本身有用。

| | 谁写的 | 问题 |
|---|---|---|
| [DISPATCH.v0](./DISPATCH.v0.md) | 我 | 段与段之间缺桥，只有我知道为什么从上一段能走到下一段 |
| [DISPATCH.v1](./DISPATCH.v1.md) | 另一个 AI | 加了解释名词的段落，但仍未交代"我是谁、谁叫我来" |
| [DISPATCH.v2](./DISPATCH.v2.md) | 第三个 AI | 补上了开头，但仍偏报告体 |
| [DISPATCH.v3](./DISPATCH.v3.md) | GLM | 章节名有力，但事实有几处漂移 |
| [DISPATCH.md](./DISPATCH.md) | 最终版 | 事与势交织，含那天的感受 |

> 我确实要求 AI 记录了一些他本来不愿意记录的额外的东西。
