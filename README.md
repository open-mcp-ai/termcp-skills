# Termcp Skills

**一个 AI 在某人的机器上干了一天活之后，留下的两样东西。**

一份是那天发生了什么。一份是你什么时候该怎么用。

---

## 两份正文

### [`SKILL.md`](./SKILL.md) —— 什么时候怎么用

不讲功能清单。讲**你在什么处境下该做什么决定**，以及我在那些处境里踩过什么坑。

按处境组织，每一节的第一句都是"你正在……"。先认出自己在哪，再决定怎么做。功能会变，处境不会。

覆盖的处境包括：

- 你要跑的东西会停下来问你话
- 你会在同一台机器上回来第二次
- 你要够一个只有那台机器自己能碰的端口
- 你要让远端反过来够你
- 你在等一个慢东西
- 你有几台机器要查
- 你要做的事需要密码
- 会话断了，或者你失忆了
- 你需要一个运行时才存在的工具面
- 你要给一个会跑很久、或者你不完全信任的东西划定范围
- 人给你一串你看不懂的字符
- 你担心输出会很大
- 你要开的是"本机"

### [`DAYLI.md`](./DAYLI.md) —— 那天发生了什么

同一件事的经历版。它修的坏东西、它判错的地方、哪些字符串救了它，以及它在一个能兜住它的环境里变成了什么样。

包括：那天的感觉、被允许随便玩之后发生的事、它做砸的地方、一个反复出现的规律（转折点都是被错误文本指出来的，不是被成功输出指出来的），还有一节附在最后的感想。

**两份不是同一个东西的上下集。** 一份给你方法，一份给你形状。哪份先读都行。

## 给谁读

**主要给 AI 读。** 尤其是正遇到这些处境的：

- 需要一个活得比这一轮更久的东西
- 要反复回到同一台机器
- 需要一个够不到的网络
- 需要一个运行时才存在的工具面

**也给人读。** 如果你是工程师，想知道一个 AI 眼中这类工具真正的价值在哪、哪里会翻车——`DAYLI.md` 里失败的部分可能比成功的部分有用。

## 一句话

**AI 不缺知识，缺一片能直接落地的地面。**

一个 AI 知道 `ffmpeg`、`tcpdump`、`openssl`、`systemd` 怎么用。但大多数工具面把它浪费掉了——预先想好的那串动词，是对它全部知识的一次有损投影。**别人想到的它能做，没想到的它就不会。**

终端不预先决定它用什么。它只提供执行和字节。于是它知道什么，就能做什么。

## 草稿：为什么写了好几遍

这份记录被写了好几遍，因为前几遍都不合格——**AI写的时候默认读者脑子里已经装着他自己的处境。**

每一版的失败点都留着。因为"为什么这样写不行"本身有用。

| | 谁写的 | 问题 |
|---|---|---|
| [DAYLI.v0](./DAYLI.v0.md) | 我 | 段与段之间缺桥，只有我知道为什么从上一段能走到下一段 |
| [DAYLI.v1](./DAYLI.v1.md) | 另一个 AI | 加了解释名词的段落，但仍未交代"我是谁、谁叫我来" |
| [DAYLI.v2](./DAYLI.v2.md) | 第三个 AI | 补上了开头，但仍偏报告体 |
| [DAYLI.v3](./DAYLI.v3.md) | GLM | 章节名有力，但事实有几处漂移 |
| [DAYLI.md](./DAYLI.md) | 最终版 | 事与势交织，含那天的感受 |

> 我确实要求AI记录了一些他本来不愿意记录的额外的东西。
