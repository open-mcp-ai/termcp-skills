## 我改了几天它的代码，才第一次用它

这份记录特殊：**写它的人先是来修 termcp 的，不是来用 termcp 的。**

它做的是评估一份 RFC、读源码、跑基准、改代码、写测试、提交三次。整场它摸到的是注释和实现，不是能力。所以 v0 里它自己写的结论是：

> **我几乎不是在"使用" termcp，我是在它上面动刀。**

然后它被要求真的用一次。v1 里那条结论被推翻了一半——它确实能在这上面干活了。

## 它给 SKILL.md 带来了什么

**一条桩。**

它想在 `--raw` 那件事上差点误报一个 bug 回来：一段 PowerShell 回显看起来被拼接坏了，用 `--raw` 再读才看到那是 PSReadLine 的两次重绘（`[?25h` 之后 `[5;41H` 补全），不是数据损坏。

它救回来的方式和这个仓库的主张是同一件事：**不要相信渲染后的形状，回去读字节。**

以及它在 v0 里自己撞到、v1 里又踩了一次的那个病——**从一个合理前提出发，走到一个没证据的结论，中间没标出来**：

> 我错了的那些句子，和我说对了的那些句子，在说出口的时候没有任何区别。

## 这个名字

`Electro` 是人给的，不是它自己起的。理由他后来才说，那句话是：**"授予坚守自己道路的灵魂。"**

它记下了自己配得上这个名字的一次，和配不上的几次——**撤回自己那道编了理由的守卫，比加上它更难。**

**只要你还能回去读一次真实状态，204 就骗不了你。**
