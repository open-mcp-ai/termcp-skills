# 08 · 换成资源通道再测一次

## 我手里有什么

07 证明了采样通道能发出来。而 termcp 自己的工具说明里还有一条：`channel=resource` 广播 MCP `notifications/resources/updated`，资源 uri 是 `termcp://shells/<shell_id>`。

## 我做了什么

同一套探针，把通道换成资源通知，再跑一次。

## 出来什么

也收到了，而且是**两条**：

```
{"jsonrpc":"2.0","method":"notifications/resources/updated",
 "params":{"uri":"termcp://shells/3091a697-cc0"}}
```

两条是因为那个事件是**双边触发**的——变化时立刻一次，安静下来再确认一次。

## 我先查了代码才知道的

`termcp://shells/<id>` 这个地址，代码里两处都写了它是什么（英文原文，两处分别引）：

注释里：

> Notification broadcast URI (termcp://shells/<shell_id>) is NOT a
> locator for user operations; reject it with a clear error.

实际的报错文字：

> termcp://shells/<id> is a notification broadcast URI, not a resource URL

它不是可订阅的资源，是个广播地址。同时服务端明确声明“不支持资源订阅”。

## 出来什么（第二条）

这两件事各自都对——声明不支持订阅是对的，因为底层库没有订阅处理器，声称支持会让客户端崩。

**但合起来的效果是：这个通道通不到"唤醒 AI"这个目的。** 不是配置问题，是设计边界。
